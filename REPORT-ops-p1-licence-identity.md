## What the grant is

`LICENSE` is the canonical BSL 1.1 text and nothing else. The parameters, at
`LICENSE:8-12`:

```
Licensor:             Cafaye
Licensed Work:        identity
Additional Use Grant: None
Change Date:          2030-10-10
Change License:       Apache-2.0
```

Change Date is four years from 2026-10-10, the interval the brief fixed and the
one BSL's own Terms name as the default (`LICENSE:27-31`). Additional Use Grant
is `None` deliberately and this is the one parameter worth a sentence: an
Additional Use Grant is a *narrowing* — "limited production use", a named subset
(`LICENSE:22-25`) — and what Cafaye Ops sells is the whole of non-competing
production use rather than a carve-out of it.

**The file is the whole of the uniformity commitment.** The brief asked that the
four repositories' `LICENSE` differ on the Licensed Work line and nowhere else,
so the text carries no repository-specific prose at all — including the
third-party-components paragraph the proprietary `LICENSE` carried before
`bb454fa`. That paragraph is a true sentence about this tree and a true
sentence about all four trees; four copies of it would be the only thing a
reader saw when they diffed them. It is stated instead at `README.md:143-145`,
which is where a reader looks for it.

## The manifest, and the finding that shaped the packet

**`identity`'s manifest is `cafaye.yml`, and it cannot carry a licence field.**
Not "does not yet" — cannot. core owns the schema,
`../core/schemas/cafaye.manifest.schema.json`, which sets
`additionalProperties: false` (line 7) and lists every key it accepts (line 9's
`properties`); `license` is in neither, and there is no `x-cafaye-` prefix escape
at the top level either. Measured rather than inferred — validating this
document with a `license: BUSL-1.1` key added returns:

```
Additional properties are not allowed ('license' was unexpected)
```

The same for `x-cafaye-license`. A licence field here would be a contract
violation, and the alternative — a manifest that disagrees with its own LICENSE —
is the failure this repository treats as a red build rather than as prose.

So the grant is declared in the three places a reader actually opens, and all
three now agree:

| file | what |
|---|---|
| `LICENSE:8-12` | the grant itself |
| `openapi/v1.yaml:277-291` | `name: Business Source License 1.1`, `identifier: BUSL-1.1` |
| `openid/openid.yaml:190-204` | the same, for the OIDC surface |
| `cafaye.yml:48-69` | a comment: the grant, and the measured reason there is no field |

Both `info.license` blocks previously read "Proprietary - All rights reserved.
See LICENSE in the cafaye/identity repository." — the m153 commit that made
identity proprietary changed `LICENSE` and both blocks together, so this
changes them back together. A contract that offered nothing while the repository
offered a grant is the same drift in the other direction.

`cafaye.yml:48-69` records the constraint so the next reader does not add a
field to "fix" the manifest, and names where the declarations are instead.
`openapi/v1.yaml:278-289` and `openid/openid.yaml:191-202` record why there is
no `url` key: `name` and `identifier` are the whole of an OpenAPI 3.1 licence
object, and `url` is mutually exclusive with `identifier` under that spec.

## Flagged, not fixed

1. **`gateway`, `courier` and `parlor` are unmeasured.** I read their `LICENSE`
   (all three still carry the "all rights reserved" text) and `parlor`'s
   `package.json:4` (`"license": "UNLICENSED"`) to confirm the starting state,
   and touched nothing outside this repository. I cannot verify that the other
   three land the same text, so the fleet's uniformity claim rests on three
   reports I have not seen. Whoever merges should diff the four `LICENSE`
   files; the only line that should differ is `Licensed Work`.
2. **`docs`' licence page is now wrong about the four services.**
   `docs/src/content/docs/licensing.md:6` states "the whole fleet is MIT" and
   `:10` counts "seven of the fifteen repositories" as carrying no licence. It
   is a different repository and a different worker's; the manager owes it a
   page that names both grants and says which is historical (OPS-D2, OPS-D3).
3. **Apache-2.0 as a Change License and BSL's own covenant 1.** Covenant 1
   (`LICENSE:72-77`) asks the Change License to be GPL-2.0-or-later or
   compatible with it. Apache-2.0 is compatible with GPLv3 and not with GPLv2,
   so "compatible with GPL Version 2.0 or a later version" is arguable rather
   than obvious. Implemented as briefed and not changed, because all four
   repositories must carry the same Change License and one worker changing it
   would be the uniformity broken. If the user wants the covenant unarguable,
   the fleet-wide edit is one parameter in four files.
4. **Conflict risk at merge is `CHANGELOG.md` and `README.md`.** The tenancy
   fleet is live in this repository. My inserts are localized — the CHANGELOG
   entry is the first block under `## [Unreleased]` (`CHANGELOG.md:9-42`), which
   is exactly where their next entry goes — so the merge needs a human on those
   two hunks. No commit of theirs was rewritten or reverted, and this branch is
   `bb454fa..1c219e6` on top of their HEAD (`35dfff1`).
5. **Two untracked files are in the worktree** and were deliberately not
   committed: `brief.txt` and `brief-lic-services-a.txt`, the dispatcher's own
   artifacts. `git status --porcelain` reports them as `??` and nothing else.
6. **`docs`' page is a different repository with a different worker.** Its own
